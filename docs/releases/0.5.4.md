# Runtime 0.5.4

[English](0.5.4.md) | [简体中文](0.5.4.zh-CN.md)

This patch is a maintainability release. It keeps the public behavior of
Runtime 0.5.3 intact and makes the code easier to audit and to extend.

## Changed

- Long functions in the provider lifecycle, the CLI maintenance paths, the
  Ledger, the migration flow, the remote gateway and the shared service now
  delegate to named helpers. Every helper keeps its original validation order,
  error type and error message.
- The provider keeps the original initialization exception. A shutdown that
  interrupts initialization still raises the stopped-initialization message.
  Teardown handlers catch `Exception`, so `SystemExit` and `KeyboardInterrupt`
  propagate instead of being swallowed.
- Repeated operator messages and configuration hints are module constants. A
  later wording change now happens in one place.
- Test assertions give one failure signal each. A `pytest.raises` block holds a
  single invocation, so a broken setup call cannot be reported as the expected
  contract violation.

## Upgrade and data compatibility

Use the normal versioned upgrade procedure. No collection schema, point
identity, Ledger schema, scope or ownership rule, configuration schema, public
tool schema, or MCP call interface changed. No data migration is required, and
existing memories are not rewritten. This release does not change the minimum
supported Hermes version.

## Install

Check that Runtime 0.5.4 is available on
[PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.4/) before
running the versioned package command.

```sh
python3 -m venv /absolute/path/runtime-env
/absolute/path/runtime-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.5.4'
```

The generic MCP distribution and the managed launcher select their own exact
Runtime dependency. They are released independently from this package.
