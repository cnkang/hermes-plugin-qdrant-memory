# Runtime 0.7.2：本地写入后保留升级恢复点

Runtime 0.7.2 带入已合并的 Runtime PR #148 中的升级计划写入水位保护。它不改
现有检索行为、点身份、已存 payload、embedding 配置、授权规则或四个受限 MCP 工具。

## 本地 Runtime 写入后不续跑旧计划

每个已保存的升级计划都会记录 profile 本地 Ledger 的当前写入水位。`apply` 与
`resume` 会在持有 profile writer lease 时重新比较。如果本 Runtime 在计划创建后
提交了写入，`status` 会报告 `write_since_plan`，`resume` 会拒绝沿用旧计划。

拒绝续跑时，旧计划和备份引用仍可供审查。操作者可以明确运行
`upgrade plan --replace`，先归档旧计划及其备份引用，再创建新计划。如果计划边界后
没有本地写入，中断后续跑会复用计划记录的备份，不会创建第二个恢复点。

**保护范围：**该水位只观察本 Runtime 写入本地 profile Ledger 的记录。它无法观察
使用独立 Ledger 的其他 Runtime 进程、其他 profile 或设备，也无法观察其他客户端对
Qdrant 的直接写入。它不保护整个 Qdrant Cloud destination。升级前请停止或隔离其他
所有 writer，并按 provider 的常规流程创建快照，确保目标集合保持稳定。

该水位只保护升级计划，不迁移数据、不更换 embedding 模型或维度、不重建集合，也不改
检索默认行为。

## 兼容性

Runtime 0.7.2 保持现有存储与策略 schema，已有记忆保留原处。无需迁移、重新嵌入或重建
索引。Hermes Catalog 与独立 MCP 发行包继续使用各自 pin；本次发布准备不更改任一 pin。

## 安装

在私有环境安装前，请先确认 [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.7.2/)
已提供该版本：

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.7.2'
```

已有 destination 请先审阅 `upgrade status` 与 `upgrade plan`。续跑中断的升级时继续使用原
计划标识。如果本地写入使计划过期，请保留恢复点，审阅 blocker 后再明确替换计划。
