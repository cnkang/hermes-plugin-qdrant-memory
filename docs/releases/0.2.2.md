# Runtime 0.2.2

[English](0.2.2.md) | [简体中文](0.2.2.zh-CN.md)

This patch supports MCP Python SDK 1.x and 2.x. SDK 1.x uses decorator-based
handler registration; SDK 2.x uses constructor callbacks. The adapter supports
both while preserving the four scoped tools, input validation and sanitized errors.
The optional dependency is `mcp>=1.30,<3`. CLI-only installations do not require it.

Install in a private Python 3.11+ environment:

```bash
pip install 'hermes-plugin-qdrant-memory[mcp]==0.2.2'
qdrant-memory --home /path/to/profile doctor
```

For environments that require a specific SDK major, install the Runtime and
either `mcp>=1.30,<2` or `mcp>=2,<3` together. No prerelease selector is required.
MCP distribution 0.1.2 pins this Runtime. Skill 0.2.5 provides installation and
usage guidance; it does not supply the Runtime.

No data migration is required. Schema-v1, IDs, scope, embedding fingerprints,
explicit writes and ledger recovery remain compatible with Runtime 0.2.1.
Retain the same profile, collection and embedding pipeline during an upgrade.
Native Hermes installations use the plugin manager; PyPI publication does not
update the separately reviewed Plugin Catalog pin.

CI exercises both SDK majors on Linux, macOS and Windows with Python 3.11 and
3.14, including official stdio protocol and explicit-write acceptance. These
checks do not certify every live agent client or embedding service.

One writer per destination remains required. Standalone MCP performs explicit
operations; automatic extraction and prefetch remain Hermes lifecycle features.
