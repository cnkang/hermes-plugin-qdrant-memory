# Runtime 0.5.0

[English](0.5.0.md) | [简体中文](0.5.0.zh-CN.md)

本版本新增可选启用的 HTTPS MCP 和自动 Owner 记忆。单个活动 Owner 控制现有
Runtime、Ledger、embedding 和 Qdrant 写入。继续支持 Embedded、自建 Qdrant
和 Qdrant Cloud。私有 profile 的现有默认行为保持不变。

## 新增能力

- `remote-serve` 在可信 TLS 代理后提供 MCP Streamable HTTP。
  监听器绑定 loopback，必须保留 TLS 校验。
- 预配置凭据绑定逻辑 Agent、设备、scope 和权限。
  设备撤销与事件重放继续执行授权校验。
- Hermes Native Owner 和显式启用的 Pi 适配器复用现有生命周期提取路径。
  客户端不能直接写入 Qdrant。
- 目的地保护与 `shared-doctor` 校验本机所有权和策略。
  持久事件保留恢复、幂等和 revision 校验。
- 可选模型 CI 区分本地冒烟、云端冒烟和云端质量测试。
  `SMOKE_PASS` 不能证明提取质量。

## 安装

```sh
python3 -m venv /absolute/path/owner-env
/absolute/path/owner-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[remote]==0.5.0'
```

仅使用本地 stdio MCP 时选择 `[mcp]`。离线 CPU embedding 还需选择 `[local]`。
配置远程访问前，请阅读 [Owner 指南](../shared-memory/remote-owner.md)。
每个客户端都需要明确授予权限。

## 升级与安全

非 loopback 的 embedding 端点现在必须使用 HTTPS，包括不携带凭据的端点。
升级前，请为现有远程 HTTP embedding 服务配置可信 TLS 代理。
继续支持 loopback HTTP。保持 embedding 模型、维度和 fingerprint 不变。

升级前停止 Owner。将 Qdrant 数据、Ledger、设备注册表和策略作为一组一致的状态备份。
不要只恢复其中一部分。启动一个 Owner，并在允许客户端接入前验证恢复。
已有记录继续可读。新的共享点标识包含 visibility。
经授权的目的地 reset 也会清除对应的准入 receipt。

MCP 发行包、Skill 快照、Hermes 目录和 npm launcher 分别选择各自已审核的版本。
本次发布不会更新这些安装。

## 验证与限制

源码基线已通过 main 的平台、standalone、安全和生命周期工作流。
发布 CI 还会测试安装后的 wheel 和源码包。
测试边界与记录结果见 [CI](../ci.md) 和[模型评估](../shared-memory/model-quality.md)。

不支持分布式多写入者、自动故障转移、OAuth 浏览器登记或组管理 UI。
本机目的地声明不能阻止持有独立数据库凭据的调用绕过 Owner。
宿主 SDK 测试不能认证 WorkBuddy 或 DSH 的用户界面。
可选模型与 Cloud 测试结果仅适用于对应运行中记录的模型、凭据和数据集。
