## Soak admission failure and correction

The full Soak workflow can admit the extended matrix while all six long-running
jobs are skipped. `cloud-smoke` is intentionally skipped when
`include_cloud=false`; `admission-gate` uses `always()` and can still set
`ready=true` after the local smoke gate passes. The `soak` job condition did not
include a status function, so GitHub applied its implicit `success()` check and
treated the skipped `cloud-smoke` ancestor as a reason to skip every extended
job. The final report then fails because the matrix was admitted but skipped.

This release-preparation change adds `!cancelled()` to the `soak` condition,
requires the admission-gate job to succeed, and keeps the explicit
`ready == 'true'` gate. Checking the job result also prevents a later summary
write failure from starting Soak after the ready output was already written.
The workflow-gate test asserts the condition. At the time of the initial draft,
readiness remained `NO`; the final main-SHA run and report have since passed as
recorded above.
