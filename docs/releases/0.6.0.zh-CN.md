# Runtime 0.6.0：可迁移的 Codex 记忆

此版本新增 Codex v1/v2 语义记忆的显式检查与导入，以及可阅读、可验证的
JSON/Markdown 交接包。原生来源、Qdrant 数据与插件安装相互独立；卸载插件
不会删除已保存的记忆和导出文件。

操作前请查看已安装版本的 `qdrant-memory codex --help`。提交导入前先预览，
并检查跳过原因。凭据形状内容、代码围栏、原始对话及不支持的文件不会通过此
适配器进入语义记忆。

交接验证核对记录 ID、正文、作用域、大小和校验和，不会把校验通过表述为
Codex 已经采用这些记忆。目的端确认实际采用前，状态仍为 `HANDOFF_PENDING`；
此版本不提供向原生记忆库批量回写的能力。

macOS/Linux 使用目录描述符锚定的 no-follow 读取。Windows 使用经检查的原生
句柄，拒绝 reparse point 和远程卷，并要求新建交接目录具备持久化的私有 ACL。
文件系统无法提供必要保证时拒绝操作。

按作用域删除也会将该作用域内的隔离事件标记为已失效。重试失败任务或重启
Provider 不会重新创建这些已删除的记忆，其他作用域的记录不受影响。

可选 CPU 后端使用官方 FastEmbed 0.9.1。Runtime 0.5.5 之前创建的 profile
可能记录了旧版 0.9.0 的管线指纹。请保留旧环境、存储和缓存；经授权导出记录，
重新嵌入到新的 profile 和 collection，验证后再切换。不要修改已有 collection
的管线指纹强行升级。具体步骤见下方 CPU 设置指南。

显式模型准备为每个文件保留 15 分钟下载窗口，仍校验大小、固定哈希并原子发布
缓存；未完成或超时的下载不会被标记为可用。
全部模型文件共享 30 分钟网络总预算；真实 CPU CI 预留 60 分钟，为依赖安装和
下载后的验收保留时间。
可取消的截止时间覆盖连接、响应头和流式正文读取，持续小片段也不能绕过。
超时后关闭网络资源、清理临时文件并释放准备锁，再允许重试。

Codex/Ollama Cloud 验收仅使用合成数据和本地 embedding 夹具，验证 harness 与
工具行为，不代表验证了 embedding 模型推理。Runtime、Python MCP、托管启动器
和 Skills 分别发布并保留独立固定引用；发布 Runtime 不会自动升级它们，也不会
发布 Codex Marketplace 候选插件。

## 安装此版本

安装前确认 PyPI 已公开 0.6.0：

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.6.0'
qdrant-memory --help
```

此命令安装无需 Hermes 的独立 CLI 和 MCP 基础组件。CPU embedding 需额外安装
`local` extra，并明确批准模型准备。记忆操作前先配置私有 profile，参见
[独立运行指南](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.0/docs/standalone.md)
和 [CPU 设置](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.0/docs/local-embedding.md)。
