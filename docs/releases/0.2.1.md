# Runtime 0.2.1 release candidate

This patch fixes explicit writes of distinct, highly similar texts without an
LLM. Runtime 0.2.0 passed an absent extractor to factual relation adjudication;
Python API, CLI and official stdio MCP calls failed on the second similar fact.
Hermes explicit tools could also skip or replace requested text through an LLM.

Explicit add now deduplicates canonical text only within the same user/agent
scope. Different texts are saved even at cosine 1.0. Automatic Hermes extraction
keeps SAME, SUPERSEDES, CONFLICT and UNRELATED adjudication. Exact-ID update
continues to replace only the authorized target. No new runtime dependency.

Schema-v1, deterministic IDs, embedding fingerprints, durable ledger and Mem0
source-ID mapping remain compatible with 0.2.0. No data migration is required.
Before an authorized upgrade, back up the profile and Qdrant destination and
verify the same profile, collection and embedding pipeline. Changing dimensions
or fingerprint fails closed; the collection is never rebuilt automatically.

After publication, in a private Python 3.11+ environment:

```bash
pip install 'hermes-plugin-qdrant-memory[mcp]==0.2.1'
qdrant-memory --home /path/to/profile doctor
```

Omit `[mcp]` for CLI only. `qdrant-memory` is the executable; `mcp` is a subcommand.
Standalone does not require Hermes. Native Hermes users should use the official
plugin mechanism rather than pip into its managed environment. PyPI does not
update the separately reviewed Hermes Plugin Catalog pin.

MCP distribution 0.1.1 pins this Runtime and remains metadata-only. Skill 0.2.4
guides supported tools and authorized installation; it supplies no runtime.
Both depend on release ordering, not matching version numbers.

Validation evidence and exact environments are recorded in [validation](../validation.md).
Existing CI covers Python 3.11/3.14, Linux/macOS/Windows, minimum Hermes and latest
main, Embedded Qdrant and disposable Server. Candidate checks must complete before
release; historical passing results are not certification of this revision.

Limits remain: one writer per destination, no distributed lock across profiles,
no automatic extraction/prefetch in standalone MCP, and durability starts only
after plugin ledger admission. Cloud and live model acceptance require dedicated
authorized resources; missing credentials do not constitute a pass.

Rollback means selecting the previously verified package/source with the same
profile and storage settings. No reverse data migration is required, but 0.2.0
restores the explicit-write defect. Do not overwrite existing tags or PyPI files.

Release order: approve/merge Runtime PR; approve tag `v0.2.1`; run protected
Trusted Publishing; verify public wheel/sdist and clean installs. Then finalize
the MCP immutable Runtime commit, approve/merge and publish `v0.1.1`, verify public
PyPI installation, and publish Registry 0.1.1. Finally accept and merge Skill
0.2.4. Each merge/tag/publication requires separate human approval.
