## Package, upgrade and public-install acceptance

- Clean Python 3.11 environments installed the final-SHA wheel and sdist.
  `python -I -m pytest --import-mode=importlib -q tests/standalone` passed
  353 tests with 0 failures and 0 skips for each artifact. `pip check`, CLI
  `--help`, and strict Twine metadata validation also passed.
- The clean public PyPI installation of 0.6.2 passed `pip check`, CLI `--help`,
  status, search and verification checks. It used the published package, not a
  source checkout.
- A disposable profile was upgraded from public 0.6.1 to the final-SHA 0.6.2
  wheel. With local Ollama `qwen3-embedding:4b`, the same record ID, text,
  scope and embedding fingerprint were preserved; verification returned
  `ok=true`, Qdrant identity matched the configured fingerprint, and SQLite
  reported `integrity_check=ok`. The public PyPI 0.6.2 install then repeated
  status, search and verification against that profile successfully.
- Synthetic local Ollama retrieval evaluation (21 memories, 24 queries) scored
  recall@1 80.56%, recall@5 98.61%, recall@10 100%, and MRR 93.06%. This is a
  synthetic evaluation, not a production recall guarantee.
- The local wheel was byte-identical across repeat builds with the same
  `SOURCE_DATE_EPOCH`. The sdist archive bytes varied because generated archive
  metadata and timestamps differ; member file contents matched the final-SHA
  source, and published wheel/sdist member contents matched the local builds.
  The release workflow does not currently set `SOURCE_DATE_EPOCH`, so archive
  byte-for-byte reproducibility is not claimed.

## Reliability follow-up and downstream compatibility

[Issue #115](https://github.com/cnkang/hermes-plugin-qdrant-memory/issues/115)
remains open. Historical Windows Python 3.14 writer-drain timeouts did not
establish data loss, duplication or ledger corruption; the current Windows
matrix and 100-turn writer-drain checks passed. The exact mechanism behind the
historical timeouts is not established, so #115 remains a reliability and test
diagnostic follow-up rather than a fixed issue.

Runtime 0.6.2 preserves the 0.6.1 Owner event and extraction interfaces. DSH
Native Owner mode remains opt-in; publishing Runtime does not change DSH Legacy,
WorkBuddy or Hermes integration pins. Each downstream integration needs its
own compatibility checks and release gate before any package pin or public
release changes.
