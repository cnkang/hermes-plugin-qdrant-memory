# Runtime 0.7.0：一套可检查、可修复的 Qdrant 策略

Runtime 0.7.0 让新装与原地升级收敛到同一套 Qdrant 策略。默认仍是 dense 检索与
float32 向量。升级不搬集合、不重嵌入、不改记忆身份，也不改召回与写入语义。

本版为每个 profile destination 增加 Runtime 策略记录，分别记录目标定义、已验收的
有效策略和实际 payload 索引。策略记录与点 payload 分离。现有 `schema_version=1`
与 embedding identity sentinel 不迁移、不改写。

## 运维升级命令

两个入口共用同一实现：

```sh
qdrant-memory --home PROFILE upgrade plan
qdrant-memory --home PROFILE upgrade apply --plan PLAN_ID
qdrant-memory --home PROFILE upgrade resume --plan PLAN_ID
qdrant-memory --home PROFILE upgrade status

hermes qdrant-memory upgrade plan
hermes qdrant-memory upgrade apply --plan PLAN_ID
```

`plan` 与 `status` 不初始化集合、不写 Ledger、不跑恢复、不建索引、不改配置。
`plan` 只保存一条控制面记录供 `apply` 引用；加 `--dry-run` 可只查看不保存。

`apply` 与 `resume` 复用现有 writer lease，并在取得维护权后重新校验已保存的 plan。
过期 plan 一律拒绝。存在待恢复的 reset、scope delete、shared receipt 或失败事件时，
必须先用既有恢复路径清空，否则拒绝升级。

## Payload 索引策略

受管索引集合来自同一份定义，`init`、`doctor`、`upgrade plan`、`upgrade apply`
共用。已有集合保留自己的索引。正常启动、普通 `init` 与 MCP 连接不再自动补建索引。

`upgrade apply` 只补齐缺失的受管索引。索引类型冲突是 blocker，附带操作步骤。
策略之外的额外索引只报告，不删除。Embedded 明确报 not applicable，不模拟已建索引。

## 恢复与回退

Embedded 升级先把已关闭的本地存储、Ledger、删除与 reset 回执以及 profile 配置复制成
恢复点，再重新打开副本并核对点数，通过后才继续。

远端升级必须同时给出 `--confirm-writers-isolated` 与 `--accept-operator-backup`，
否则拒绝执行。本版不持有 Qdrant 管理备份权限。

应用版本回退不等于存储降级。不要用旧 Server 或旧 embedded 客户端直接打开新版写过的
数据。按同一停写检查点整体恢复备份；该检查点之后的新增与删除会随恢复一起丢弃。

## Qdrant 版本

Qdrant Server 1.20.1 是推荐且已演练的自托管基线。受控 Runtime 环境锁定
`qdrant-client==1.20.0`。公开依赖范围仍是 `qdrant-client>=1.15,<2`，因此裸 PyPI
安装可能解析到该范围内的其他客户端。只有受控环境与发布验收是精确固定。

升级演练保留 1.20.0 镜像作为夹具：同一卷原地升级、复制停写卷、恢复到新卷，再比对
点、payload、向量与索引。

Server 与 Cloud 只检测版本、能力与权限。版本查不到时显示 `unknown` 及其受限能力。
Embedded 保留本地后端，没有独立 Server。

## 本版不含

跨集合复制或重嵌入、alias 切换、BM25/RRF、MMR、时效排序、ACORN、tenant/HNSW 图、
量化与 sparse 回填都留到后续。诊断可以显示探测到的能力，但不会自动启用。

## 安装

安装前先确认 [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.7.0/)
已可见：

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.7.0'
```

Hermes Catalog 安装需等待另行评审的 Catalog repin，然后执行
`hermes plugins update qdrant-memory` 并重启 Hermes。Runtime 发布不会自动更新 Catalog。

## 升级说明

从 0.6.3 或 0.6.2 升级时保持同一 profile、集合与 embedding pipeline。已有 destination
继续以 dense 路径服务，在被显式 apply 之前显示为 `legacy`。先跑 `upgrade plan`，
审阅 blocker 与索引状态，再在短维护窗口内 apply。

从 0.5.4 升级的 Catalog 用户必须保持同一 embedding pipeline 才能复用集合。可选 CPU
FastEmbed extra 已从 0.9.0 变为 0.9.1，即使模型与维度相同，fingerprint 也会变化。
保留旧环境与数据。不要按维度相同推断可复用，也不要覆盖 identity sentinel。

上一版变更见 [0.6.3 发布说明](0.6.3.zh-CN.md)。
