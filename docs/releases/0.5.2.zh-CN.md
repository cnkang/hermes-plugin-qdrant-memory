# Runtime 0.5.2

[English](0.5.2.md) | [简体中文](0.5.2.zh-CN.md)

两台设备上的 24 小时云端 soak 发现：重启可能让客户端把写入视为终局。23 条写入未到达 Ledger，
其余重启断连只丢失响应。客户端把两种情况都当作终局。本补丁关闭这一契约缺口。
本版本不改变 schema、collection 标识、凭证格式或工具 schema。

## 修复

- 远程客户端把重启断连、连接重置、MCP 流中断、超时、408/429/502/503/504 响应
  与 Owner 的显式重试判定归为可重试。错误信封给出应重放的标识。
- 适配器对快速失败最多重放两次，并保持同一 request 或 event 标识。
  Owner 返回已存回执，因此一次写入仍只产生一条记录。
- 认证、重定向、TLS、scope、版本冲突与业务拒绝仍为终局。
  已接收但需运维恢复的请求报告 `recovery_required`，请求保留在 Owner。
- `remote-call` 与 `remote-event` 的 CLI 错误信封包含 `reason`、`retryable` 与 `replay`。
  工具拒绝保留 Owner 的对象，该对象可能只含 `type` 与 `retryable`。
  把 `SharedRecoveryRequiredError` 读作“请求已保留”，不要当作已丢弃。
  决策记录见[远程写入重试](../design/remote-write-retry-adr.md)。
- 隔离仍只适用于没有 prepared 计划的确定性提取失败。
  prepared 或已提交阶段的失败仍保留 Owner 恢复门禁。

## 安装

运行版本化安装命令前，请确认 Runtime 0.5.2 已在
[PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.2/) 公开。

```sh
python3 -m venv /absolute/path/owner-env
/absolute/path/owner-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[remote]==0.5.2'
```

仅本地 stdio MCP 时选择 `[mcp]`。需要离线 CPU embedding 时再加 `[local]`。

## 升级

升级前停止 Owner。把 Qdrant 数据、Ledger、设备注册表、受保护 claim 与 policy 作为
一个一致集合备份。本版本没有迁移步骤。用同一 profile 启动新的 Owner。

遵守 `retryable` 的客户端现在必须重放同一个 `request_id` 或 `event_id`。
忽略该字段的客户端行为不变。

## 验证与限制

本地套件通过 1142 项测试，0 失败，11 项受门控跳过。
[重启边界记录](../validation/restart-boundary-retry-2026-10.md)列出故障注入证据与
未执行的检查。

0.5.0 的限制不变。没有分布式多写入者、自动故障转移、OAuth 浏览器授权或群组管理界面。
慢失败仍依赖调用方的持久 outbox。Owner 已接收但未提交的请求需要运维恢复。
