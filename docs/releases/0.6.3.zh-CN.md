# Runtime 0.6.3：显式声明 Hermes 兼容下限

两份原生插件 manifest 均声明 `requires_hermes: ">=0.21.5"`，以符合当前
Hermes Catalog 要求，并让目录与安装包加载器执行同一下限。兼容下限没有提高。
相对 0.6.2，Runtime 行为、依赖、工具 schema、存储格式和 embedding 指纹不变。

可选 Shared Owner 仍默认关闭，保留 0.6.2 的收据级恢复：授权重试仅重新排队原事件
计划中失败的操作，不重新提取整轮对话，不重排无关写入；隔离事件仍由运维人员控制。

## 安装与升级

确认 [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.6.3/) 已发布后，
在独立环境安装 `hermes-plugin-qdrant-memory[mcp]==0.6.3`。Catalog 安装需等待单独
审核的 repin，再运行 `hermes plugins update qdrant-memory` 并重启 Hermes。

从 0.6.2 升级可保留同一 profile、collection 和 embedding 管线；升级后先执行
`qdrant-memory status` 与 `qdrant-memory verify`。

从 Catalog 0.5.4 升级时，可选 CPU FastEmbed 由 0.9.0 变为 0.9.1，即使模型和维度
相同，embedding 指纹也会改变，旧 CPU collection 不能直接复用。保留旧环境和数据，
需要切换时先导出，再在新 profile、collection 中重新嵌入。Catalog PM 不安装可选
CPU extra。保持原 Ollama 模型和配置的用户不受此 FastEmbed 变化影响。

此前的行为改进参见 [0.6.2 发布说明](0.6.2.zh-CN.md)。
