# Runtime 0.5.3

[English](0.5.3.md) | [简体中文](0.5.3.zh-CN.md)

此补丁修复 WriterLease 冲突或其他初始化异常后可能出现的 Provider 生命周期故障。
只有资源和写入 worker 均就绪后，Provider 才会进入可用状态。初始化失败时，会先清理本次
尝试创建的资源，清理完成后才允许显式重试。

## 修复

- `WriterBusyError` 会让 Provider 进入可诊断的失败状态，不再留下半初始化对象。
  生命周期 Hook 和工具不会访问不存在的 Ledger 或 Runtime。
- 无法持久化事件时，自动持久化回调会明确失败。要求可靠证据的压缩前检查点仍然 fail closed。
  不可用工具返回脱敏的结构化错误；预取安全返回无建议结果。
- 关闭资源前先停止接纳事件。如果 Native listener 或其他清理回调尚未成功停止，会继续保留
  WriterLease。回归测试覆盖初始化与关闭竞争、部分 SQLite 初始化、worker 启动和显式重试。
- 失败尝试清理完成后，Host 可以显式重新初始化同一个 Provider。Runtime 不会在后台循环重试
  被占用的 Lease：竞争写入者可能长期存活。如果 Host 不会重建失败 Provider，请先停止冲突
  写入者，再重启受影响的 Hermes 进程或 Gateway。

## 升级与数据兼容性

先停止所有冲突写入者，再按常规的版本固定升级流程操作。本版本不改变 collection schema、
point identity、Ledger schema、scope 或归属规则、配置 schema、公共工具 schema、MCP 调用接口，
也不改变最低 Hermes 版本。无需迁移数据，现有记忆不会被重写。

不要通过删除锁文件解决 writer 冲突。确认持有目的地写入权的进程已正常关闭，再使用 Host
支持的 Provider 重启或重建流程。Runtime WriterLease 只保护本机进程/profile，不是跨主机的
分布式锁。

## 安装

运行版本化安装命令前，请确认 Runtime 0.5.3 已在
[PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.3/) 公开。

```sh
python3 -m venv /absolute/path/runtime-env
/absolute/path/runtime-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.5.3'
```

Hermes 原生插件请使用 README 中固定版本的源码安装方式。升级后重启 Hermes 或 Gateway。
MCP 分发包和 Qdrant Memory Skill 有各自独立的发布流程和精确 Runtime pin。

## 验证与限制

本地 Python 3.11 与 3.14 套件各通过 1227 项测试，14 项由环境门控跳过。使用固定摘要的隔离
Qdrant Server 运行 HTTP/gRPC 与真实 WriterLease 竞争测试（3 项通过，1 项未选择），设备端
Server 测试 2 项通过。这些结果不代表已验证认证 Cloud、跨机器 fencing、准备好的本地模型
缓存或每个 Hermes Host 版本。具体本地证据和剩余发布门禁见[验证记录](../validation.md)。
