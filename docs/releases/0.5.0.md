# Runtime 0.5.0

[English](0.5.0.md) | [简体中文](0.5.0.zh-CN.md)

This release adds opt-in HTTPS MCP and automatic Owner memory. One active
Owner controls the existing Runtime, Ledger, embeddings and Qdrant writes.
Embedded, self-hosted Qdrant and Qdrant Cloud remain available.
Private profiles keep their existing defaults.

## Added capabilities

- The `remote-serve` endpoint uses MCP Streamable HTTP behind a trusted TLS
  proxy. The listener binds to loopback. TLS verification remains required.
- Provisioned credentials bind logical agents, devices, scopes and permissions.
  Device revocation and event replay retain authorization checks.
- Hermes Native Owner and the opt-in Pi adapter use the existing lifecycle
  extraction path. Clients cannot write directly to Qdrant.
- Destination protection and `shared-doctor` check local ownership and policy.
  Durable events retain recovery, idempotency and revision checks.
- Optional model CI separates local smoke, cloud smoke and cloud quality.
  `SMOKE_PASS` does not establish extraction quality.

## Install

Check that Runtime 0.5.0 is available on [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.0/)
before running the versioned package command.

```sh
python3 -m venv /absolute/path/owner-env
/absolute/path/owner-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[remote]==0.5.0'
```

For local stdio MCP only, select `[mcp]`. For offline CPU embeddings, also
select `[local]`. Read the [Owner guide](../shared-memory/remote-owner.md)
before configuring remote access. Each client needs an explicit grant.

## Upgrade and security

Non-loopback embedding endpoints now require HTTPS, including endpoints without
a credential. Put a trusted TLS proxy in front of an existing remote HTTP
embedding service before upgrading. Loopback HTTP remains supported.
Keep the embedding model, dimensions and fingerprint unchanged.

Stop the Owner before upgrade. Back up the Qdrant data, Ledger, device registry,
protected claim and registry, Owner configuration and policy as one consistent
set. Restore the complete matching set before starting an Owner. Keep the old
Owner stopped during host migration. Local claims do not coordinate two hosts.
Start one Owner and verify recovery before admitting clients.
Existing records remain readable. New shared point identities include visibility.
An authorized destination reset clears its admission receipts too.

MCP distributions, Skill snapshots, the Hermes catalog and npm launchers select
their own reviewed versions. This release does not update those installations.

## Validation and limits

The source baseline passed the main platform, standalone, security and lifecycle
workflows. Release CI also tests the installed wheel and source archive.
See [CI](../ci.md) and [model evaluation](../shared-memory/model-quality.md)
for test boundaries and recorded outcomes.

There is no distributed multi-writer mode, automatic failover, OAuth browser
enrollment or group administration UI. Local destination claims do not prevent
an independent database credential from bypassing the Owner. Host SDK tests do
not certify WorkBuddy or DSH user interfaces. Optional model and Cloud results
apply only to the model, credentials and dataset recorded in each run.
