# Runtime 0.5.2

[English](0.5.2.md) | [简体中文](0.5.2.zh-CN.md)

A 24-hour two-device cloud soak found that a restart could drop an admitted
write. 23 writes never reached the ledger, and other restart cuts lost only the
response. The client reported both cases as final. This patch closes that
contract gap. No schema, collection identity, credential format or tool schema
changed.

## Fixed

- The remote client classifies a restart cut, a reset stream, a broken MCP
  stream, a timeout, a 408/429/502/503/504 answer and an explicit Owner retry
  verdict as retryable. The error envelope names the identifier to replay.
- The adapter replays a fast failure two times with the same request or event
  identifier. The Owner returns its stored receipt, so one write stays one
  record.
- Authentication, redirect, TLS, scope, revision and business rejections remain
  final. An admitted request that needs operator recovery reports
  `recovery_required`, and the Owner keeps the request.
- The CLI error envelope for `remote-call` and `remote-event` carries `reason`,
  `retryable` and `replay`. A tool rejection keeps the Owner object, which can
  carry only `type` and `retryable`. Read `SharedRecoveryRequiredError` as a
  retained request, not as a discarded one. The decision record is
  [remote write retry](../design/remote-write-retry-adr.md).
- Quarantine still applies only to a deterministic extraction failure with no
  prepared plan. A prepared or committed failure keeps the Owner recovery gate.

## Install

Check that Runtime 0.5.2 is available on [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.2/)
before running the versioned package command.

```sh
python3 -m venv /absolute/path/owner-env
/absolute/path/owner-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[remote]==0.5.2'
```

For local stdio MCP only, select `[mcp]`. For offline CPU embeddings, also
select `[local]`.

## Upgrade

Stop the Owner before the upgrade. Back up the Qdrant data, the Ledger, the
device registry, the protected claim and the policy as one consistent set.
This release adds no migration step. Start the new Owner against the same
profile.

A client that honors `retryable` must now replay the same `request_id` or
`event_id`. A client that ignores the field keeps its previous behavior.

## Validation and limits

The local suite passed 1130 tests with 0 failures and 11 gated skips. The
[restart-boundary record](../validation/restart-boundary-retry-2026-10.md) lists
the fault-injection evidence and the checks that were not run.

The limits of 0.5.0 remain. There is no distributed multi-writer mode,
automatic failover, OAuth browser enrollment or group administration UI.
A slow failure still depends on the caller's durable outbox. A request that the
Owner admitted but did not commit needs operator recovery.
