# Runtime 0.4.0

[English](0.4.0.md) | [简体中文](0.4.0.zh-CN.md)

This release adds an opt-in authenticated local shared owner and a stdio bridge
for explicit shared memory. One Runtime process owns the store, the embedding
service, the SQLite ledger and the writer lease. Authorized clients reach one
explicit space through a private loopback API. Legacy records stay private.

The release keeps the existing private behavior:

- The Hermes Native Provider, the standalone stdio MCP command and the managed
  profiles do not change.
- Installation does not reconfigure a profile.
- The four MCP tools keep their schemas.
- Optional offline CPU embedding, trusted setup and MCP Python SDK 1.x/2.x
  support remain available from 0.3.0.

## Shared owner commands

The standalone CLI adds three explicit commands:

```bash
qdrant-memory --home /path/to/owner-profile shared-serve
qdrant-memory --home /path/to/owner-profile shared-call
qdrant-memory --home /path/to/owner-profile shared-mcp
```

`shared-serve` starts the owner. `shared-call` and `shared-mcp` connect a client
to that owner. A client profile holds no storage and no embedding model.

## Install

```bash
python3 -m venv /absolute/path/shared-runtime-env
/absolute/path/shared-runtime-env/bin/pip install 'hermes-plugin-qdrant-memory[mcp]==0.4.0'
/absolute/path/shared-runtime-env/bin/qdrant-memory --home /absolute/path/owner-profile doctor
```

The [shared memory guide](../shared-memory/README.md) records the policy file,
the grants and the host walkthrough. Use a separate owner profile. Do not run
these commands against an existing production profile for experiments.

## Security boundary

The owner binds to `127.0.0.1` only and uses bearer credentials. A token maps to
one principal, one space and one permission set. A read-only grant cannot
mutate. Malicious code that runs as the same OS user is outside the credential
boundary. Do not expose the service through a public proxy.

The repository records one Sonar rule exception for `python:S5332` on the
reviewed local transport. All other security rules and quality thresholds stay
active. See the [architecture note](../shared-memory/architecture.md).

## Compatibility

Schema-v1, point IDs, scope, embedding fingerprints, explicit writes and ledger
recovery remain compatible with Runtime 0.3.0. No data migration is required.
Shared mode adds an additive request and receipt table only when an operator
uses the feature.

## Limits

- No distributed multi-writer, remote API, OAuth or group administration.
- No automatic migration from a private space to a shared space.
- No Native Provider automatic shared extraction.
- Receipts are retained. No compaction policy is released.
- Windows private file ACLs remain operator-managed.

## Validation

The full local suite and the hosted platform matrix passed. The
[validation report](../shared-memory/report.md) records the accepted scenarios,
the recovery cases and the measured results.
