# Runtime 0.6.1: durable lifecycle retry

This patch release adds an authenticated Owner lifecycle retry action for
durably accepted events. The Owner already stores the immutable event plan with
its receipt. A retry names only the event ID; the Owner reuses that plan and
returns its status without returning candidate content.

This lets a native harness adapter recover an accepted turn after a lost
response or restart without keeping candidate text in the harness session log
or extracting the turn again. The adapter and Owner continue to use the same
device grant, event identity and receipt.

Runtime 0.6.0 features, storage formats and security defaults remain unchanged.
The existing lifecycle endpoint remains opt-in.

## Install this release

Confirm version 0.6.1 is available on PyPI before installing:

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.6.1'
qdrant-memory --help
```

This installs the standalone CLI and MCP base without Hermes. Add the `local`
extra for optional CPU embeddings. Model preparation requires explicit approval.
Configure a private profile before memory operations. See the
[standalone guide](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.1/docs/standalone.md)
and [CPU setup](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.1/docs/local-embedding.md).
