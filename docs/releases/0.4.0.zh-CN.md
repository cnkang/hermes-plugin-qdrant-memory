# Runtime 0.4.0

[English](0.4.0.md) | [简体中文](0.4.0.zh-CN.md)

本版本新增显式启用的本地认证共享 owner 与 stdio 桥接，用于明确的共享记忆场景。
一个 Runtime 进程持有存储、Embedding 服务、SQLite ledger 和 writer lease。
已授权客户端通过私有回环 API 访问一个明确的共享空间。旧记录继续保持私有。

本版本保持原有私有行为：

- Hermes Native Provider、独立 stdio MCP 命令和托管 profile 均不改变。
- 安装过程不会重新配置 profile。
- 四个 MCP 工具的 schema 保持不变。
- 0.3.0 的可选离线 CPU Embedding、受信初始化以及对 MCP Python SDK 1.x/2.x 的支持继续可用。

## 共享 owner 命令

独立 CLI 新增三个显式命令：

```bash
qdrant-memory --home /path/to/owner-profile shared-serve
qdrant-memory --home /path/to/owner-profile shared-call
qdrant-memory --home /path/to/owner-profile shared-mcp
```

`shared-serve` 启动 owner。`shared-call` 和 `shared-mcp` 将客户端连接到该 owner。
客户端 profile 不持有存储，也不加载 Embedding 模型。

## 安装

```bash
python3 -m venv /absolute/path/shared-runtime-env
/absolute/path/shared-runtime-env/bin/pip install 'hermes-plugin-qdrant-memory[mcp]==0.4.0'
/absolute/path/shared-runtime-env/bin/qdrant-memory --home /absolute/path/owner-profile doctor
```

[共享记忆指南](../shared-memory/README.zh-CN.md)记录了策略文件、授权和宿主接入步骤。
请使用独立的 owner profile。不要在现有生产 profile 上做试验。

## 安全边界

owner 仅绑定 `127.0.0.1`，并使用 bearer 凭证。一个 token 对应一个主体、一个空间和一组权限。
只读授权不能执行写操作。以同一操作系统用户身份运行的恶意代码不在凭证边界内。
不要通过公共代理暴露该服务。

仓库为本地传输保留一条 Sonar `python:S5332` 规则例外。其他安全规则和质量阈值全部保持启用。
参见[架构说明](../shared-memory/architecture.md)。

## 兼容性

schema-v1、point ID、作用域、Embedding 指纹、显式写入和 ledger 恢复与 Runtime 0.3.0 兼容。
不需要数据迁移。只有在运维方启用共享模式时，才会新增请求与回执表。

## 限制

- 不提供分布式多写入者、远程 API、OAuth 或组管理。
- 不提供从私有空间到共享空间的自动迁移。
- 不提供 Native Provider 自动共享提取。
- 回执会保留。当前不发布压缩策略。
- Windows 私有文件 ACL 由运维方管理。
