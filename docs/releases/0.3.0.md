# Runtime 0.3.0

[English](0.3.0.md) | [简体中文](0.3.0.zh-CN.md)

This release adds an optional, explicitly selected CPU embedding provider and
the trusted `prepare-model` and `setup` commands. The default remains Ollama.
CPU embedding is never selected because Ollama or a cloud service happens to be
unavailable. Ollama and OpenAI-compatible configurations keep their existing
defaults and identities.

The CPU provider uses the multilingual MiniLM-L12-v2 model (384 dimensions).
The ONNX artifacts come from the
[Qdrant collection](https://huggingface.co/Qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q)
with pinned revisions, SHA-256 verification and offline startup. It rejects
input beyond the model's 128-token limit. The dependency set is the optional
`local` extra. A prepared model cache is about 252 MB.

`setup` initializes only a new private embedded profile. It preserves writer
ownership and recovery, and it refuses configuration changes on repeat calls.
`prepare-model` fetches and verifies the model artifacts. Interrupted
preparation no longer blocks a retry, and lock contention reports a distinct
busy state.

Install in a private Python 3.11+ environment:

```bash
pip install 'hermes-plugin-qdrant-memory[mcp]==0.3.0'
qdrant-memory --home /path/to/profile doctor
```

For the CPU provider, add the `local` extra:

```bash
pip install 'hermes-plugin-qdrant-memory[mcp,local]==0.3.0'
```

No data migration is required. Schema-v1, IDs, scope, embedding fingerprints,
explicit writes and ledger recovery remain compatible with Runtime 0.2.2.
Retain the same profile, collection and embedding pipeline during an upgrade.
Native Hermes installations use the plugin manager. PyPI publication does not
update the separately reviewed Plugin Catalog pin.

CI exercises Linux, macOS and Windows with Python 3.11 and 3.14. The optional
CPU embedding job prepares the pinned artifacts and runs the real offline model
acceptance on the three systems with Python 3.11. These checks do not certify
every live agent client or embedding service.

The MCP distribution pins a verified Runtime revision. Its Runtime 0.3.0 update
follows in the MCP repository. Skill 0.2.6 provides installation and usage
guidance. It does not supply the Runtime.

One writer per destination remains required. Standalone MCP performs explicit
operations. Automatic extraction and prefetch remain Hermes lifecycle features.
