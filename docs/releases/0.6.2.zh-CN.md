# Runtime 0.6.2：按收据恢复失败事件

Runtime 0.6.2 为已持久化、后来进入 `FAILED` 状态的 lifecycle event 增加按收据恢复能力。经过授权的重试会校验事件保存的操作计划，只重新排队该事件中失败的操作，并将事件恢复为 `PENDING`。它不会重置无关写入，也不会重新提取对话。`QUARANTINED` 事件仍由运维人员显式处理；计划无效时会拒绝重试。

Runtime 0.6.1 的既有行为、SQLite Ledger 格式、Qdrant collection schema、向量维度、Embedding 指纹、Scope 边界和 WriterLease 行为保持不变。无需迁移数据或重新生成 Embedding。Owner lifecycle 路由仍为 opt-in，并继续执行现有授权和 Scope 检查。

## 安装

安装前请确认 PyPI 已公开 0.6.2：

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.6.2'
qdrant-memory --help
```

这会安装独立 CLI 和 MCP 基础依赖，不需要 Hermes。可选 CPU Embedding 使用 `local` extra；认证 Owner 服务使用 `remote` extra。模型准备仍需明确批准。执行记忆操作前请配置私有 profile。参见[独立运行指南](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.2/docs/standalone.md)、[CPU 设置](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.2/docs/local-embedding.md)和[Owner 指南](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/v0.6.2/docs/shared-memory/remote-owner.md)。

## 从 0.6.1 升级

安装到当前使用目标私有 profile 的环境中。继续使用原 profile、Qdrant collection 和 Embedding 管线。升级后先运行 `qdrant-memory status` 和 `qdrant-memory verify`，再恢复写入。本版不会自动重试失败事件；客户端必须使用相同事件收据发起经过授权的重试请求。

发布 Runtime 不会自动发布或更新通用 MCP 分发包、Codex 插件、DSH bundle、WorkBuddy 启动器或 Hermes Plugin Catalog。每种集成都保留自己的版本 pin 和发行检查。
