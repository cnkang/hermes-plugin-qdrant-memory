# Runtime 0.5.1

[English](0.5.1.md) | [简体中文](0.5.1.zh-CN.md)

本补丁修复受保护 Owner 的恢复路径。两台设备上 OpenCode 与 Pi 的验收发现了这些缺陷。
本版本不改变 schema、collection 标识或凭证格式。

## 修复

- `retry` 接受 `--policy`，可打开已登记的 destination。此前该命令 fail-closed，
  保留的工作无法重新入队。显式 policy 仍受调用目录约束与私有状态检查。缺少该参数时
  仍按原样拒绝。
- 相对 `--home` 现在在 CLI 边界统一解析。`verify`、`list`、`stats`、`doctor` 与
  `retry` 的行为与绝对路径一致。
- 无法解析的 `--home` 现在返回脱敏 JSON 错误，而不是 traceback。
- loopback HTTPS 监听在 POSIX 上复用端口。正常停止后立即重启不再报地址占用。
  Windows 保持关闭该套接字选项，因为该平台会把它当作共享活动端口的许可。

## 安装

运行版本化安装命令前，请确认 Runtime 0.5.1 已在
[PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.1/) 公开。

```sh
python3 -m venv /absolute/path/owner-env
/absolute/path/owner-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[remote]==0.5.1'
```

仅本地 stdio MCP 时选择 `[mcp]`。需要离线 CPU embedding 时再加 `[local]`。

## 升级

升级前停止 Owner。把 Qdrant 数据、Ledger、设备注册表、受保护 claim 与 policy 作为
一个一致集合备份。本版本没有迁移步骤。用同一 profile 启动新的 Owner。

已登记的 destination 需在 policy 所在目录执行恢复命令，`--home` 使用绝对路径。

```sh
qdrant-memory --home /absolute/path/owner retry --policy ./owner-policy.json
```

## 验证与限制

本地套件通过 1076 项测试，0 失败，11 项受门控跳过。
[跨设备验收记录](../validation/cross-device-opencode-pi-2026-10.md)列出测试矩阵、证据与
尚未解决的限制。发布 CI 会测试安装后的 wheel 与源码包。

0.5.0 的限制不变。没有分布式多写入者、自动故障转移、OAuth 浏览器授权或群组管理界面。
确定性的提取失败仍会阻塞所有写入，直到运维修复模型并重试。
