# Runtime 0.7.2: retain the upgrade recovery point after local writes

Runtime 0.7.2 carries the upgrade-plan write-watermark protection merged in
Runtime PR #148. It preserves the existing retrieval behavior, point identity,
stored payloads, embedding configuration, authorization rules and four scoped
MCP tools.

## A plan cannot resume across a local Runtime write

Each saved upgrade plan records the current write watermark from its profile's
local Ledger. `apply` and `resume` compare that value again while holding the
profile writer lease. If this Runtime committed a write after the plan was
created, `status` reports `write_since_plan`, and `resume` refuses to continue
with the old plan.

The refusal keeps the old plan and its backup reference available for review.
An operator can explicitly run `upgrade plan --replace` to archive that plan
and backup reference before creating a fresh plan. With no local write across
the plan boundary, resuming an interrupted upgrade reuses its recorded backup
instead of creating a second recovery point.

**Scope boundary:** the watermark observes writes recorded by this Runtime in
the local profile Ledger. It cannot observe another Runtime process using a
separate Ledger, another profile or device, or direct writes from other clients
to Qdrant. It does not protect an entire Qdrant Cloud destination. Stop or
isolate every other writer and take the provider's normal snapshot before an
upgrade that requires a stable destination.

The watermark does not migrate data, change embedding models or dimensions,
rebuild the collection, or change retrieval defaults. It is upgrade-plan
protection only.

## Compatibility

Runtime 0.7.2 keeps the existing storage and policy schemas. Existing memories
remain in place. No migration, re-embedding or index rebuild is required.
Hermes Catalog and the independent MCP distribution keep their own pins; this
release preparation does not change either pin.

## Installation

Check [PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.7.2/) for
availability before installing in a private environment:

```sh
python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.7.2'
```

For an existing destination, review `upgrade status` and `upgrade plan` before
applying. Keep the original plan identifier when resuming an interrupted
upgrade. If a local write made the plan stale, retain its recovery point and
review the blockers before explicitly replacing it.
