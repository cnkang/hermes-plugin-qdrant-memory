# Runtime 0.5.3

[English](0.5.3.md) | [简体中文](0.5.3.zh-CN.md)

This patch fixes a provider lifecycle failure that can follow WriterLease
contention or another exception during initialization. A provider is now usable
only after its resources and writer worker are ready. Failed initialization
closes the resources created by that attempt before a later explicit retry.

## Fixed

- A `WriterBusyError` leaves the provider in a diagnosable failed state instead
  of a partially constructed state. Lifecycle hooks and tools do not access an
  absent Ledger or Runtime.
- Durable callbacks report failure if they cannot persist an event. A required
  pre-compression checkpoint still fails closed. Unavailable tool calls return
  a redacted structured error; prefetch safely returns no suggestion.
- Cleanup stops admission before closing resources and retains the WriterLease
  if a native listener or another cleanup callback has not stopped successfully.
  Initialization and shutdown races, partial SQLite setup, worker startup, and
  explicit retry are covered by regression tests.
- The provider can be explicitly initialized again after failed-attempt cleanup
  completes. The Runtime does not retry a busy lease in a background loop: a
  competing writer may remain active indefinitely. If the Host does not rebuild
  a failed provider, stop the conflicting writer and restart the affected Hermes
  process or Gateway.

## Upgrade and data compatibility

Stop conflicting writers and use the normal versioned upgrade procedure. No
collection schema, point identity, Ledger schema, scope or ownership rule,
configuration schema, public tool schema, or MCP call interface changed. No
data migration is required, and existing memories are not rewritten. This
release does not change the minimum supported Hermes version.

Do not delete a lock file to resolve a writer conflict. Confirm that the process
holding the destination's writer has shut down cleanly, then use the Host's
supported provider restart or reconstruction path. A Runtime WriterLease is
local process/profile protection; it is not a distributed lock across hosts.

## Install

Check that Runtime 0.5.3 is available on
[PyPI](https://pypi.org/project/hermes-plugin-qdrant-memory/0.5.3/) before
running the versioned package command.

```sh
python3 -m venv /absolute/path/runtime-env
/absolute/path/runtime-env/bin/python -m pip install 'hermes-plugin-qdrant-memory[mcp]==0.5.3'
```

For native Hermes use the version-locked source installation in the README.
Restart Hermes or its Gateway after upgrading. The MCP distribution and Qdrant
Memory Skill use separate release processes and exact Runtime pins.

## Validation and limits

Local Python 3.11 and 3.14 suites passed 1,227 tests each with 14 environment-
gated skips. A disposable, pinned Qdrant Server passed the HTTP/gRPC and real
WriterLease contention lane (3 passed, 1 not selected) and device-server tests
(2 passed). These results do not certify authenticated Cloud, cross-machine
fencing, prepared local-model caches, or every Hermes host version. See the
[validation record](../validation.md) for the exact local evidence and remaining
release gates.
